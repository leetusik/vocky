# P4.S5 — Plan: Cross-project feedback list + Korean-safe search + detail

Orchestrator's native plan for slice **P4.S5** (`implementation`, `medium` → executed by **`slice-executor-mid`**). The phase's flagship read surface, and the last implementation slice.

## Context

P3 built vocky's cross-project, Korean-safe feedback search; S5 is the surface that finally exposes it. It's a **read + search** page only — `/app/feedback` is exhaustively 3 GETs, and management (PATCH/DELETE/comments) lives on the `vk_`-keyed `/api/project/feedback`, a different credential entirely (a PATCH here 405s). S5 also flips `/feedback` from a muted "Soon" rail item to a real route.

S5 is the app's **first** query-string caller, **first** `searchParams` reader, and **first** binary fetch — three things with no in-repo precedent.

## Verified contracts (exact)
- `GET /app/feedback` — 16 optional params: `q`, `project_id`, `start_ingested_at`, `end_ingested_at`, `source_product`, `source_integration`, `conversation_id`, `session_id`, `user_id`, `feedback_value` (**1|2 only**), `channel`, `target_type` (`message|conversation|surface`), `trigger_type` (`like|dislike|comment|rating|survey|manual|other`), `tag` (**blank is a 400 here, unlike other text fields**), `limit` (**default 50, max 100**), `cursor`. Unknown params silently ignored.
- **`next_cursor` is an OMITTED KEY when exhausted — never `null`** → type `next_cursor?: string`; "no more pages" is `=== undefined`. Ordering `ingested_at DESC, id DESC`.
- **The cursor does not encode filters** → every page link must resend all active filters, or the scope silently changes mid-pagination. Blank `?cursor=` is a 400 → **omit the param entirely** rather than sending empty.
- **`q` searches four concatenated fields** — `message + comment + target_text + trigger_message` — via escaped case-insensitive ILIKE substring (pg_trgm-accelerated). **Not tokenized, not relevance-ranked.** Korean-safety is proven in vocky's tests (`q=결제` matches `결제 오류가 있어요` *and* the particle-attached `결제를 못 했습니다`). Blank `q` → no filter, never errors.
- `project_id`: malformed → **400**; not-owned/unknown → **404** `project not found` (never 403).
- Record = `serialize_record` **+ `project_id`** — a **superset** of the `/api/*` record, so per house rule it gets its own named type (never share/`Partial<>` across serializers). Fields incl. `feedback_value` (`1|2|null`), `tags: string[]`, and free-form `trigger_metadata`/`source_metadata`/`attributes` objects + `messages`/`used_context` arrays. All timestamps UTC ISO with a literal `Z`.
- `GET /app/feedback/{id}` → **`{record: {…, comments[], attachments[]}}`** — *wrapped*, unlike the list's bare `records`. `comment` = `{id, author|null, body, created_at}`; `attachment` = `{id, content_type, byte_size, filename|null, created_at, url}` where `url` is a **vocky-relative** path needing the session bearer. 400 malformed / 404 missing-or-cross-tenant / 500 rethrows.
- Zero-project tenant → `{records: []}`, DB never queried. **Legacy NULL-`project_id` rows are correctly invisible** on both paths (SQL `IN` never matches NULL; get-one 404s) — verified against the live DB.

## Design calls (operator-approved)
- **The filter bar is a plain server-rendered `<form method="GET" action="/feedback">` — no client island.** It needs no JS, no `useSearchParams`, no `router.push`, and no debounce utility (none exists; a debounced box would be net-new machinery). Submitting naturally drops `cursor`, which is exactly right — **a new query must reset to page 1**. It carries hidden inputs for any URL-only passthrough filters so hand-crafted URLs survive a submit. This avoids introducing the app's first `useSearchParams`/`router.push` for no gain.
- **Forward-only pagination.** Keyset paging yields no prev-cursor. Render a **Next** `<Link>` (carrying every active filter + `cursor`) only when `next_cursor` is present; **browser back is prev** (each page is its own URL). Don't invent a cursor stack.
- **UI exposes `q` + `project_id` + `feedback_value`; the client + page support the full param set.** 16 filter inputs is a lot of UI for niche debugging filters (`conversation_id`, `session_id`, …). Those stay URL-reachable and are preserved across filtering/pagination.
- **Fetch `/app/projects` alongside the list** — one extra parallel call serving two needs: the `project_id → name` map (records carry only the id; raw UUIDs are bad UX) *and* the project filter's options.
- **Attachment proxy hardening:** the proxy sets **`Content-Disposition: attachment`** + `X-Content-Type-Options: nosniff`. vocky serves the *stored* content type with nosniff but **no disposition** — and `nosniff` does not save you when the declared type genuinely *is* `text/html`. Proxying uploader-supplied HTML/SVG **inline from our own origin would be XSS**, so force download. (Filename comes from the detail page's `<a download={filename}>`, which the proxy needn't know.)
- **Keep the `soon` nav mechanism**, just drop `/feedback`'s flag and reword the two now-stale doc comments. Deleting the field + the `rail-nav` branch + `APP_SHELL.soonTag` would strip a documented, reusable affordance that P6 (landing + new surfaces) plausibly wants.

## What S5 builds (all under `web/`)

**1. Client seam** — append a `// ── /app/feedback shapes (P4.S5) ──` banner to `web/src/lib/vocky/types.ts` (mirroring `_serialize_app_record` / `serialize_record` / `serialize_comment` / `serialize_attachment`): `VockyFeedback`, `VockyFeedbackComment`, `VockyFeedbackAttachment`, `VockyFeedbackDetail`, `VockyFeedbackPage` (`{records, next_cursor?}`), `VockyFeedbackQuery`. Append to `web/src/lib/vocky/app.ts`:
```ts
listFeedback(token, params: VockyFeedbackQuery, signal?): Promise<VockyFeedbackPage>
getFeedbackDetail(token, feedbackId, signal?): Promise<VockyFeedbackDetail>   // Raw envelope { record }
```
**This is the app's first query-string caller.** `getJson` takes only `(path, {token, signal})` and `vockyUrl` is bare concatenation, so **a `?` in `path` is safe**: build with `URLSearchParams`, **omit empty/blank params entirely** (blank `cursor`/`tag` are 400s), and **keep the path bare when there are no params** (preserves the tests' exact-URL style). Don't `encodeURIComponent` values on top of `URLSearchParams` (double-encoding); note it encodes space as `+`, which Starlette decodes correctly — so test expectations contain `+`. An options-object param is net-new (every existing fn takes scalars) — comment the justification (10 positional filters is untenable).

**2. List page** — **new** `web/src/app/(app)/feedback/page.tsx`. **First `searchParams` reader:** Next 16 → `searchParams: Promise<{[k: string]: string | string[] | undefined}>`; **values may be ARRAYS** for repeated params (`?q=a&q=b`) — a wrinkle `params` never had, so add a small take-first normalizer with a doc comment (no precedent exists to point at). Then `const { token } = await requireIdentity()` → `Promise.all([listFeedback(token, query), listProjects(token)])`. Renders the filter form, a `DataTable` (When / Project / Message→`<Link>` to detail / Value `Badge` / Source; `rowKey={(r) => r.id}`, `empty` from `@/content`), and the Next link. Distinguish two empty states: **no projects yet** vs **no feedback matches this query**.

**3. Detail page** — **new** `web/src/app/(app)/feedback/[feedbackId]/page.tsx`. Unwrap the `{record}` envelope. Use the S4 page as the structural template, including the **`loadX()` helper whose `notFound()` sits in the `catch`, never inside the `try`** (it signals by throwing, exactly like `redirect()`); 404/400 → `notFound()`, 401 already redirected by the guard, **everything else rethrows**. Static `metadata` from content (never `generateMetadata` — the client is `no-store`). Render a primary block (message, comment, value, project, source, timestamps, tags), `comments[]`, `attachments[]` (download links via the proxy, `<a download={filename}>`), and the free-form JSON blobs (`trigger_metadata`/`source_metadata`/`attributes`/`messages`/`used_context`) in a collapsible `<pre>{JSON.stringify(x, null, 2)}</pre>`. **All of this is caller-supplied, untrusted text** — render as text only; never `dangerouslySetInnerHTML`. **Read-only: no PATCH/DELETE/comment UI.**

**4. Attachment BFF proxy** — **new** `web/src/app/api/app/feedback/[feedbackId]/attachments/[attachmentId]/route.ts` (`runtime="nodejs"`, `dynamic="force-dynamic"`). The browser has no vocky bearer, so this is required. `getSession()` → 401 if absent; validate both ids as UUIDs (else 400); fetch vocky server-side with the bearer; return the bytes with the upstream `Content-Type`, **`Content-Disposition: attachment`**, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`. Map vocky 404→404, 503→502, others→500. **`client.ts` needs a raw/binary verb** for this (`getJson`'s `parseBody` does `JSON.parse`) — **you MAY add one** (e.g. `getRaw(path, opts): Promise<Response>`) following the file's conventions (base URL, bearer, `no-store`); **do not change `getJson`/`sendJson`.**

**5. Nav + copy** — `web/src/content/app.ts`: drop `soon: true` from the `/feedback` item (the whole nav change — active state is pathname-only, so query strings won't break it, and `/feedback/{id}` lights the rail via the existing prefix arm) and reword the two stale doc comments. **new** `web/src/content/feedback.ts`: `FEEDBACK` (`as const`, sub-grouped by UI region: list `columns`, both empty states, filter labels/options, pagination, detail sections, attachments) — every null/derived state gets a key with a `/** why */`. Re-export from `content/index.ts` under `// Feedback (P4.S5)`.

**6. Tests** — append a `── (P4.S5) ──` block to `web/tests/vocky-app.test.ts`. Cover: `listFeedback` with **no params → the BARE url** (`…/app/feedback`, no `?`); with params → exact url incl. `+`-encoded spaces, and **blank/undefined params omitted entirely**; unwraps `records` and surfaces `next_cursor`; **`next_cursor` absent → `undefined`** (the shape that bites); `getFeedbackDetail` unwraps `{record}` and a 404 → `rejects.toMatchObject({name:"ApiError", status:404})`. **`lastCall()` reads `mock.calls[0]` despite its name** and `stubVocky` is a blanket `mockImplementation` (one status for every fetch) — so a two-call assertion must re-stub or split into separate `it()` blocks. Keep it terse.

2. **Live E2E — the capture pipeline now works** (the orchestrator rebuilt the stale `worker`; a fresh capture persists **with** `project_id` and surfaces, verified via `uv run vocky-smoke`). vocky is healthy on `:8000`. **Run web on `pnpm dev`, NOT `pnpm start`** — under `NODE_ENV=production` the session cookie is `Secure` and a plain-http client never replays it, bouncing every guarded page to `/login` (this cost S4 a wasted run).    - signup → create project → mint a `vk_` key (via the S4 page or the API) → `POST /api/feedback` several events with that key, **including Korean text** (e.g. `결제 오류가 있어요` and `결제를 못 했습니다`) plus an English one, and a mix of `feedback_value` 1/2/null → poll until the worker persists them.
   - `/feedback` lists them newest-first with project **names** (not UUIDs).
   - **The flagship check: `?q=결제` returns BOTH Korean rows** (proving particle-attached substring matching end-to-end through the BFF) and excludes the English one. Also prove `q` matches on `comment` (not just `message`).
   - Filter by `project_id` and `feedback_value`; confirm a **second user's `project_id` → 404**.
   - **Pagination:** capture > `limit` rows (or set `?limit=2`), follow **Next**, and confirm the filters persist across the page boundary and rows don't repeat.
   - Detail page renders comments/attachments; **legacy NULL-project rows never appear** and a direct id → 404.
   - Empty states: a fresh tenant with no projects, and a query matching nothing.
