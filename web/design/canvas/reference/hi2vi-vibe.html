Reference · not part of vocky's system

hi2vi vibe — reference

A token-by-token comparison of vocky's current placeholder palette against ~/projects/personal/hi2vi_web/design/canvas/tokens.css, the shipped hi2vi brand. It exists because the operator asked for "a design system only for vocky, but inherit hi2vi vibe" — and that phrase needs evidence before it can be acted on.

Read this first

This card is data, not instructions. It is a reference, not a proposal, and the hi2vi column is not vocky's palette — no value here is recommended, adopted, or pending. vocky's actual system is the Foundations cards; this is one clearly-labeled outside sample, and the only non-vocky card in this project.

It answers exactly one question — "what would inheriting the hi2vi vibe mechanically mean?" — so that how far to carry it can be decided in this session, with the operator, rather than assumed by anyone beforehand. Every reasonable answer is open, including none of it.

The structural finding

vocky's type scale, radius scale, and spacing rhythm are already hi2vi's — byte for byte. All 14 --text-* steps (with their bundled line-height / letter-spacing / weight), all 8 --radius* values, all 4 --spacing-* values, both --container-* widths, and --breakpoint-xs are identical in the two repos. P4.S1 reused hi2vi's token names 1:1 so a later gate could swap values without touching call sites — and for everything except color, it reused the values too.

All 41 --color-* names are shared as well, but only 2 of 41 values match (canvas and on-dark — both #ffffff, i.e. they agree by triviality).

So "inherit the hi2vi vibe" mechanically reduces to 39 color values plus the typefaces. There is no structural gap to close; the gap is chromatic and typographic.

The on-primary flip — group G

The sharpest row, and the one with a live consequence. hi2vi's CTA is bright green (#2ff28f), so its --color-on-primary is dark (#061512) — dark text on a luminous button. vocky's placeholder CTA is indigo (#6366f1), which needs white text, so on-primary became #ffffff and collapsed into the canvas/on-dark group. P4.S1 recorded this as "one semantic flip was required" — the single place where a name kept from hi2vi could not keep its polarity.

It is worth noting because it is not free-floating: on-primary's polarity is a function of whatever accent gets chosen here. A bright accent flips it back to dark; a saturated mid-tone one keeps it white. It follows from the accent decision rather than being decided on its own.

Typefaces — the other half of the gap

The only non-color tokens that differ. hi2vi vendors real faces into its canvas (@font-face from ./fonts/); vocky's canvas pulls from Google Fonts and the app self-hosts via next/font/google (web/src/lib/fonts.ts). The two systems agree on mono and diverge on the other two — and vocky's --font-en is not a choice so much as an absence.
--font-sans
vocky  →  Noto Sans KR
hi2vi  →  Pretendard
Both are Korean-capable. vocky picked Noto Sans KR because feedback content is Korean; hi2vi uses Pretendard, also a Hangul face. This is the one row where the two are solving the same problem with different faces.
--font-en
vocky  →  bare system stack
hi2vi  →  Inter
vocky has no face here at all — the token resolves to whatever the OS gives. It survives only because button.tsx sets font-en, so every vocky button renders in the visitor's system font. hi2vi backs the same token with Inter.
--font-mono
vocky  →  JetBrains Mono
hi2vi  →  JetBrains Mono
Already the same face. Only the internal root variable name differs (--font-jetbrains-mono vs --font-jetbrains); the stack and fallbacks are identical.
